Timestamped Tezuka firmware for the **HamGeek Fishball Pluto+ (Zynq 7010 + AD9363)**: **srsRAN 4G up to 50 PRB (10 MHz) without overclock**.

### What's new since v0.1.0
- **sdr_ip_gadget with UDP GSO** (`UDP_SEGMENT`): each RX buffer goes through the kernel network stack once instead of once per packet. Packets on the wire are unchanged (no client change). Max timestamped RX rate **8.3 → 12.2 MS/s** (16-bit). Patch and numbers: `firmware/sdr_ip_gadget/`.
- **8-bit samples packed by the FPGA** (Tezuka's CS8 logic, active when channel Q is disabled): new SoapyPlutoSDR argument `ip_cs8=1` (patch in `srsran/soapy-ip-cs8.patch`, Docker variable `IP_CS8=1`). Half the bytes over DMA and network, no CPU conversion on the board: max RX **17.4 MS/s**. 8-bit is fine for 64QAM.
- srsRAN board CPU load (30 s average): 25 PRB **35 %** (16-bit) / **9 %** (8-bit), 50 PRB 8-bit **43–80 %**, vs 94 % at 25 PRB with the original gadget. 50 PRB: 4 late TX blocks out of 160,000 over 160 s.
- **srsRAN Docker image**: device discovery with `hostname=` fixed (Avahi scan fails in containers), `PRB=50`, `IP_CS8`, `charge.sh` load test.
- **Eco mode**: orphan stream watchdog — if a client is killed without stopping its stream, `sdr_ip_gadget` is restarted after 2 minutes (`ORPH_DELAI`), so the board goes back to sleep.
- Overclock (CPU950/DDR600) measured and **not needed** (it gave 11.4 MS/s with the original gadget, +4–5 °C, out of spec). CPU frequency scaling / DDR power-down: no gain, not used.

### Upgrade
Copy the new `tezuka-fishball-ts.zip` contents to the SD card (keeps `eco.conf` defaults). On the PC, rebuild the `srsran/` image for `IP_CS8=1`.
